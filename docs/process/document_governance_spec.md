# 文档治理规范

## 1. 目的

本规范用于约束 `new_robot_code` 仓库中的文档分层，避免：

1. 过程草稿散落在仓库根目录或代码目录。
2. 多个文档重复维护同一份稳定事实。
3. 临时调试记录长期混入正式说明。

## 2. 文档类型划分

### 2.1 公开说明文档

放在 `docs/` 下，面向仓库使用者和后续开发者，内容包括：

1. 项目概况
2. 协作规范
3. 文档治理规范
4. 仿真参考
5. 其他稳定的长期说明

要求：

1. 必须可长期复用。
2. 不应夹带临时实验结论或未收敛讨论。

### 2.2 过程文档

当后续需要记录需求推演、调试过程、阶段计划时，统一放在：

```text
docs/internal/active/issue_<编号>_<slug>/
```

要求：

1. 过程文档只服务于进行中的任务。
2. 不应直接作为长期规范引用。

### 2.3 稳定决策

当某个过程结论已经稳定，并且需要长期约束实现时，应提炼进：

1. 对应公开规范文档，或
2. 未来单独的 ADR 目录

禁止长期同时维护“过程结论版”和“正式规范版”两份事实。

## 3. 当前仓库的正式事实源

目前建议的事实分工：

1. `docs/project_overview.md`
   - 仓库边界、目录、构建入口、owner 边界
2. `docs/process/git_collaboration_spec.md`
   - Git 协作规则
3. `docs/process/document_governance_spec.md`
   - 文档分层与治理规则
4. `docs/matlab_simulation_reference.md`
   - 当前正式控制链路的仿真相关事实

## 4. 维护原则

1. 公开文档只写稳定事实，不写聊天式记录。
2. 仿真参数、动作语义、控制公式只在仿真参考文档集中维护。
3. 项目概况只做总览与导览，不重复抄写参数表。
4. 协作文档只写规则，不混入具体任务过程。

## 5. 禁止项

1. 禁止在仓库根目录保存临时过程草稿。
2. 禁止在多个正式文档里重复维护同一份参数表。
3. 禁止把未验证的调试结论直接写入正式规范。
4. 禁止让代码注释、过程文档、正式说明三处同时维护同一决策事实。

## 6. 后续演进建议

如果后续文档规模继续增长，建议增加：

```text
docs/internal/active/
docs/internal/archive/
docs/adr/
```

但本轮先不扩目录，只先把规则写清楚，避免在独立仓库初始化阶段过度铺陈。
